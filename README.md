# 工时统计系统

一个用于值班、排班、工时统计和模板修订的前端单页工具。项目当前以 GitHub Pages 方式发布，入口文件为 `index.html`。

支持的核心能力：

- 人员管理
- 工时类型管理
- 按天录入
- 按周统计
- 按周修订
- 模板导入 / 套用
- 排班表转模板
- 导出 Excel
- 本地 `localStorage` 持久化

## GitHub Pages

- 仓库 Pages 地址通常为：`https://<你的 GitHub 用户名>.github.io/<仓库名>/`
- GitHub Pages 默认读取仓库根目录下的 `index.html`
- 如果想直接使用根域名形式访问，需要把仓库名改成 `<用户名>.github.io`

## 用户手册

### 推荐流程

1. 维护人员名单
2. 配置工时类型
3. 用“排班转模板”整理周模板
4. 切到“按周 - 修订模式”应用模板并完成换人
5. 切回“按天”逐格核对统计差异
6. 最后进入导出预览并导出 Excel

### 核心界面

- 顶部工具栏：切换按天 / 按周、日期导航、导入记录、导入模板、排班转模板、导出
- 左侧边栏：人员搜索、隐藏零工时、人员列表、模板状态
- 主区域：按天统计、按周统计、按周修订
- 弹窗区域：工时类型、人员导入、模板预览、排班转模板、导出预览

### 按周模式

按周模式分为两个子模式：

- `统计`：查看本周各人员每日工时和周合计
- `修订`：基于模板附带的原始视图，对当前周进行可视化修订

#### 周修订模式说明

- 左侧显示与原 Excel 基本一致的原始视图
- 已识别到的人员槽位会按工时类型着色
- 第 1 次点击已识别槽位：删除该槽位当前人员，并扣除对应工时
- 第 2 次点击空槽位：直接在该槽位位置弹出搜索框
- 输入姓名或拼音首字母后，可直接选择替补人员补入当前槽位
- 第 3 次点击同一已选槽位：恢复模板原数据

显示差异开启后：

- 浅色主题使用黑色边框
- 深色主题使用白色边框
- 红色空框表示模板中原本有数据，但当前周已被清空

### 排班表转模板

“排班表转模板”分三步：

1. 上传 Excel
2. 规则与映射
3. 原始视图确认并保存模板

支持的规则：

- 姓名映射规则：把别名映射到系统人员
- 类型关键词规则：命中关键词后强制归入某个工时类型
- 星期关键词规则：处理非标准周几写法
- 忽略关键词规则：忽略不应识别为人员的文本

第三步会显示：

- 与原 Excel 布局一致的原始表格预览
- 合并单元格结构
- 已识别人员按工时类型着色
- 自动列宽缩放
- 连续 5 行以上空白区折叠
- 缩放查看

建议先把模板在这里校准干净，再保存供按周修订使用。

### 模板导入与套用

支持两类模板来源：

- 通过“排班转模板”识别并保存的周模板
- 从系统导出的工时明细重新导入得到的模板

套用规则：

- 按周视图：覆盖当前整周
- 按天视图：只覆盖当前日期对应的星期列

注意：模板套用会替换目标范围内已有记录。

### 显示差异

导入模板后可以打开“显示差异”：

- 按天：显示当前计数与模板计数的差值
- 按周统计：显示当前小时数与模板小时数的差值
- 按周修订：用边框和空框显示替换情况

### 导出预览与奖励工时

导出前会先进入预览页，可切换：

- `按天预览`
- `按周预览`

预览表中会：

- 显示每列工时
- 在总计前新增 `奖励工时` 列
- 允许手动录入本次导出的奖励工时

奖励工时只影响本次导出的统计表，不会写回日常记录。

导出文件包含：

- `小时统计(按日)`
- `小时统计(按周)`
- `工时明细`

其中 `工时明细` 可以再次导回系统恢复记录。

### 数据保存

系统不依赖后端，默认保存到浏览器本地。刷新页面后，下列内容会保留：

- 人员名单
- 工时类型
- 工时记录
- 隐藏状态
- 自动隐藏设置
- 主题
- 排班解析规则库
- 流程面板折叠状态
- 当前缓存模板
- 周修订覆盖状态

周修订覆盖状态会按“模板名 + 周起始日期”分开保存，因此不同模板和不同周的修订结果不会互相覆盖。

## 开发者手册

### 技术栈

- `React 18 UMD`
- `ReactDOM 18`
- `Babel Standalone`
- `SheetJS xlsx`
- `pinyin-pro`
- `localStorage`

### 目录结构

- `index.html`：页面入口和主要 React 组件
- `assets/css/styles.css`：全局样式
- `assets/js/core.js`：工具函数、排班解析逻辑
- `.bak/`：本地备份目录，已加入 `.gitignore`

### 当前本地存储键

主要键包括：

- `wh_personnel`
- `wh_types`
- `wh_records`
- `wh_hidden`
- `wh_autohide`
- `wh_theme`
- `wh_schedule_rules`
- `wh_flow_collapsed`
- `wh_template`

周修订覆盖缓存使用动态键：

- `wh_revision_overrides::<模板名>::<周起始日期>`

### 模板结构

通过“排班转模板”保存的模板除 `data` 外，还会附带 `preview` 数据，主要用于周修订模式：

- 原始网格 `rawGrid`
- 合并单元格信息 `rawMerges`
- 单元格识别类型 `cellMatchType`
- 单元格工时类型 `cellTypeName`
- 槽位映射 `cellSlotMap`

### 主要组件

- `App`：应用状态、导入导出、模板套用
- `DayView`：按天录入与核对
- `WeekView`：按周统计 / 按周修订
- `WorkflowPanel`：操作流程面板
- `ScheduleImportModal`：排班表转模板
- `TemplateViewModal`：模板预览
- `CalendarPicker`：日期与周切换
- `ExportModal`：导出预览与奖励工时录入

### 运行方式

直接打开 `index.html` 即可。

如需本地静态服务：

```powershell
python -m http.server 8080
```

然后访问 [http://localhost:8080](http://localhost:8080)。

### 维护说明

- 当前项目仍是单页 UMD 结构，适合继续做中小规模迭代
- 功能逻辑主要在 `index.html`，纯工具和解析逻辑已抽到 `assets/js/core.js`
- UI 样式统一维护在 `assets/css/styles.css`
- 如果后续继续做大规模 UI 重构，建议先保持“功能逻辑不动，只改样式和局部 JSX 结构”的策略

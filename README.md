# 工时统计系统

一个基于前端单页的工时管理工具，核心围绕三类数据运行：
- 记录数据（实际工时记录，唯一事实来源）
- 模板数据（周模板基线，用于差异对比与批量写入）
- 识别框架（排班表识别与模板生成能力）

当前线上入口：`index.html`（GitHub Pages）。

## 1. 系统核心设计

### 1.1 数据分层

1. 记录数据（Records）
- 存储每日、每人、每类型的实际记录条目。
- 每条记录包含自己的 `hours`（实际工时），以及绝对定位字段（如 `absSlotKey`、`absRow`、`absCol`）和相对可读信息（`rowLimit`、`colLimit`）。
- 因此同一种工时类型可以在不同日期、不同周拥有不同实际工时；修改类型默认值不会追溯改写历史记录。
- 业务计算（按天/按周工时、导出统计）以记录数据为准。

2. 模板数据（Template）
- 包含模板统计结构（`data`）和原始视图结构（`preview`）。
- 模板本身不等于当前周记录，默认不直接改写记录数据。
- 用于：
  - 差异视图基线
  - 周修订槽位定位
  - 显式“写入模板数据”操作

3. 识别框架（Schedule Parser）
- 将排班 Excel 解析为模板。
- 由“姓名映射、类型关键词、工时规则、星期关键词、忽略词”等规则驱动。
- 输出可复用模板，并保留原始网格供周修订与原始视图查看。
- 可识别修订视图导出的带版本标记 JSON 单元格：解析时先恢复 `baseValue` 参与原排班识别，再把姓名/时间/奖励工时/备注保存为模板元数据，避免 JSON 文本破坏排班结构。

4. 周修订标注（Revision Annotations）
- 独立于日常工时记录和模板基线，按“周起始日 + 模板 ID + Excel 单元格坐标”保存。
- 用于记录无法归入固定任务时点的姓名、时间、奖励工时和备注。
- 奖励工时不改写日常记录，只在导出统计时自动加入“奖励工时”列。

### 1.2 关键原则

- 模板数据与记录数据隔离：
  - `替换当前模板` 只切换模板基线，不修改记录。
  - `写入模板数据` 才会改记录。
- 周修订按绝对定位映射：
  - 实际操作以 `absSlotKey / absRow / absCol` 为主。
  - 相对坐标（行限位/列限位）仅用于显示理解。

### 1.3 默认工时理论规则

- 洗抹布 / 洗板擦布：1h。
- 晚巡：统一按 1h 计；周日普通晚巡不再自动翻倍。
- 晚上值日 / 值日：1h。
- 值班：优先按排班表中的实际起止时间计算，例如 `7:05-9:35` = 2.5h。
- 晚巡负责人：每日两个区域合计 1h；周日两个区域合计 2h。系统会把共享额度分摊到当日负责人槽位，避免两个区域重复累计。
- “负责人”文字不是必需字段。若巡视表首个人员行没有类型标签，系统只将其列为“负责人候选”，不会直接计时；导入时可一键采用“同日同名、跨两个区域”的成对候选，也可逐个勾选。确认后才按负责人规则计时。

## 2. 用户操作流程（推荐）

1. 维护人员与工时类型
- 在“人员”“工时类型”中先完成基础配置。

2. 生成或选择模板
- 使用“排班转模板”导入排班表并保存模板，或从模板库选择已有模板。

3. 指派当前周模板
- 点击“替换当前模板”：仅替换本周模板基线并可开启差异视图。

4. 周修订（按绝对槽位 + 非人员位置标注）
- 切换到“按周 -> 修订”。
- 人员槽位继续支持删除/替换。
- 如需记录临时奖励，打开“编辑非人员位置”，点击任意非人员单元格填写“姓名 / 时间 / 奖励工时 / 备注”。
- 新增或修改的非人员标注属于本周差异；开启“显示差异”后，HTML 表格只显示姓名，并在右下角以小号数字显示奖励工时，不显示时间和备注。
- 人员槽位修订继续落到记录数据；非人员标注独立保存在周修订数据中。

5. 按天核对
- 回到“按天”检查卡片明细（行限位/类型/移动/删除）。

6. 导出
- 导出内容改为多选，可一次选择“按日统计 / 按周汇总 / 工时明细 / 修订视图”，每项分别生成一个 Excel 文件。
- 时间范围默认“最近一个月”（以最近记录日期向前 30 天），也可选择全部记录或自定义范围。
- 文件名统一为 `工时统计_YYYY.MM.dd-YYYY.MM.dd_导出模式.xlsx`，例如 `工时统计_2026.09.07-2026.09.30_修订视图.xlsx`。

## 3. 主要功能说明

### 3.1 按天视图
- 显示每人每类型记录卡片。
- 卡片显示该条记录的实际工时，而不是只显示类型默认工时。
- 卡片支持删除、移动到其他人员。
- 差异模式下可看到“新增/移出”条目。

### 3.2 按周视图
- 统计模式：按周汇总每人每日工时。
- 修订模式：基于模板原始网格进行槽位级替换。
- “编辑非人员位置”开关默认关闭；开启后可在非人员单元格建立或修改周修订标注。
- 标注字段：姓名、时间、奖励工时、备注。姓名可自由输入，但只有与人员库姓名精确匹配时，其奖励工时才会自动汇入按日/按周导出统计。
- 标注只在“显示差异”开启时以“姓名 + 右下角奖励工时”形式出现；时间和备注保留在数据中，不挤占 HTML 网格。

### 3.3 模板管理
- 模板库支持新增、删除、指派。
- 模板查看为原始视图（raw grid），用于核对槽位布局。

### 3.4 排班转模板
- 三阶段：上传 -> 规则校准 -> 原始视图确认并保存。
- 工时规则可直接维护“关键词 / 基础工时 / 周日倍率”，制度变化时无需改代码。
- 无标签负责人采用“候选 -> 人工确认”机制：默认仅标出巡视表首个人员行；推荐使用“一键采用成对候选”，即同一天同一姓名同时出现在两个巡视区域的高置信候选。
- “采用全部结构候选”和逐个勾选用于版式特殊的周；负责人候选选择只作用于本次导入，不把 Excel 行号固化为全局规则，避免下周版式变化后误识别。
- 未确认的负责人候选不会进入模板，也不会产生负责人工时。
- 生成模板同时保留 `preview.rawGrid / rawMerges / cellSlotMap`，负责人条目额外保存 `role / leaderSource / hoursReason` 便于后续追溯。
- 若导入文件来自“修订视图”导出，形如 `{"__wh_revision_cell__":1,...}` 的 JSON 单元格会被兼容识别：`baseValue` 恢复为原表内容继续参与排班解析，修订字段保存到 `preview.cellAnnotations`。

### 3.5 批量工时
- 顶部“批量工时”可按当天或当前周筛选记录。
- 可按工时类型、负责人、晚巡、值日、洗抹布、按时段值班等角色批量选择。
- 支持一键应用理论规则、设为 1h / 2h、乘 2、恢复类型默认值或输入自定义工时。
- 批量修改只影响当前选择的日期范围，不会联动修改其他周。

### 3.6 导出
- 导出内容为多选：`按日统计 / 按周汇总 / 工时明细 / 修订视图`；所选内容分别导出为独立文件，不再使用单选“日 + 周”模式。
- 默认时间范围为“最近一个月”，另支持“全部记录”和“自定义范围”。
- 文件命名：`工时统计_YYYY.MM.dd-YYYY.MM.dd_导出模式.xlsx`。
- 明细和汇总均按每条记录保存的实际工时计算；重新导入带工时列的导出文件时会保留实际工时。
- 周修订标注中的奖励工时会在导出按日/按周统计时自动汇总到对应人员的“奖励工时”列；导出窗口仍保留“本次额外奖励”输入，两者相加但均不回写日常记录。
- `工时明细` 文件若存在周修订奖励，会额外附带“奖励工时”sheet，记录周起始日、单元格、姓名、时间、奖励工时和备注。
- `修订视图` 文件把非人员标注编码为单元格 JSON 字符串，字段包含版本标记、`baseValue / name / time / rewardHours / note`，便于再次“排班转模板”时无损识别。

## 6. 版本迁移提示

如果你是旧版本用户，请注意：
- “模板 = 基线”已替代“模板直接代表当前周记录”的旧理解。
- 周修订点击操作已按绝对位置映射，避免同类行限位联动误改。
- 查看模板以原始视图为主，统计视图仅用于汇总理解。
- 首次载入旧版记录时，会把当时的类型默认工时快照写入每条旧记录，后续再修改默认类型工时不会改变历史周。
- 新增的 `wh_week_cell_annotations` 与旧数据完全独立；旧用户升级后默认为空，不会改变既有记录或模板。
- 从修订视图导出的 JSON 单元格可再次作为“排班转模板”输入；模板中的历史标注仅作为模板元数据保留，不会自动重复计入新周奖励，只有本周新建/修改的周修订标注才进入奖励汇总。

## 2026-10-02 R2：修订视图复核链路

修订视图导入现在按“复核数据”处理，而不是作为新模板的永久基线：

1. 导入包含 `__wh_revision_cell__` JSON 的修订视图并保存；
2. 对该修订视图模板执行“写入模板数据”时，JSON 中的姓名、时间、奖励工时、备注会写入当前周的复核标注层；
3. 随后选择真实排版模板并点击“替换当前模板”，只替换当前周的对比基线，不清除复核标注；
4. 进入周修订并打开“显示差异”后，复核标注仍按 Excel 坐标显示，其中 HTML 单元格显示姓名 + 右下角小号奖励工时；
5. 奖励工时同时进入该周导出的自动奖励统计。

复核标注按周保存，与具体 `templateId` 解耦；在当前周真实模板上继续人工编辑时，新的人工修改仍按模板级覆盖保存。


## 2026-10-02 R3：写入复核数据后立即可见

针对“修订视图写入数据后，奖励标注只有替换真实模板并显示差异才出现”的问题，本版调整复核写入行为：

1. 修订视图包含 JSON 复核标注时，“写入模板数据”固定按**整周**写入，不受当前处于按天/按周视图影响；
2. JSON 标注仍写入当前周 `__review_import__` 复核层，奖励工时不写入普通任务工时，避免污染基础工时；
3. 写入成功后自动切换到 **按周 → 修订**，并自动开启“显示差异”；因此复核姓名和右下角奖励工时应在写入完成后立即可见；
4. 随后再选择真实排版模板执行“替换当前模板”，仅替换对比基线；复核层继续保留，差异显示不消失；
5. 对真实样例中的 `H6`，预期写入完成后立即显示 `艾力`，右下角显示 `2.0h`，而普通任务工时统计保持不变。
